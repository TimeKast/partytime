## 1. Objetivo

Verificar que la capa de datos dice la verdad: que el schema Drizzle (`lib/schema.ts`), las migraciones SQL (`drizzle/`), los tipos TypeScript (`types/event.ts`, `types/event-settings.ts`) y las queries (`lib/queries.ts`, `lib/user-queries.ts`) están alineados entre sí y con lo que la app realmente lee/escribe. El foco es la clase de drift que produjo el bug real del commit `eb7aa9a` (faltaba `rsvpClosed` en el type `Event` de `types/event.ts` aunque existía en DB y la UI lo necesitaba): **tipos mentirosos, firmas engañosas, columnas sin migración, JSONB sin shape validado y queries que operan sobre claves ambiguas (slug vs id)**.

## 2. Contexto mínimo (sesión fría)

- Stack de datos: **Drizzle ORM + Neon PostgreSQL** vía `@neondatabase/serverless` con driver **neon-http** (`lib/db.ts:1-16`). Ojo: neon-http **no soporta transacciones** — toda secuencia multi-statement es no atómica.
- `db` puede ser `null` si falta `DATABASE_URL` (`lib/db.ts:13-16`); todas las queries hacen guard `if (!db) throw` (p.ej. `lib/queries.ts:25`).
- **Gotcha central del proyecto:** `rsvps.eventId` (columna `event_id`, tipo `text`, `lib/schema.ts:83`) almacena el **SLUG** del evento, no el UUID. Evidencia: `app/api/rsvp/route.ts:49` (`eventId = event.slug`) y `app/api/rsvp/route.ts:227-228` ("Get RSVPs using the slug (as stored in eventId field)"). En cambio `events.id` (`lib/schema.ts:13`) sí es el identificador primario (UUID generado en app — pero ver ítem 15: es `text`, no tipo `uuid`, y existe al menos un id legacy no-UUID).
- Migraciones: carpeta `drizzle/` con solo 2 archivos SQL (`0000_add_og_image_url.sql` — que en realidad es el CREATE inicial completo de las 6 tablas — y `0001_add_rsvp_closed.sql`, ALTER manual). Journal en `drizzle/meta/_journal.json` registra **solo** la 0000. Scripts npm: `db:generate`, `db:push`, `db:studio` (`package.json:10-12`) — la existencia de `db:push` sugiere que columnas posteriores se aplicaron con push directo sin generar migración.
- Cron de recordatorios: `GET/POST /api/cron/send-reminders` cada 12h en UTC (`vercel.json`); selecciona eventos con `getEventsWithPendingReminders()` (`lib/queries.ts:459-487`) usando ventana de "hoy" en UTC.
- Historia relevante: `eb7aa9a` (drift de tipo, el arquetipo de esta auditoría), `43cf503` (display_title), `263506b` (plus_one_name), `e8f4e57` (rsvp_closed), y `scripts/fix-rsvp-event-link.ts` (script one-off que reparó rsvps huérfanos por cambio de identificador — evidencia de que la orfandad ya ocurrió en producción).
- **Producción con datos y usuarios reales.** Nada de esta auditoría ejecuta escrituras contra la DB.
