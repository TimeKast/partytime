### Design decisions (rev. history of the authoring plan)

- **ID scheme — hook-safe + ordered.** Epics `EPIC-NN-{slug}` (number-at-front), issues `{DOMAIN}-{NNN}` with a **global topological sequence** (gap-10) unique across `project/backlog/**`. Single `[A-Za-z]+-[0-9]+` token + filename = ID-prefix → compatible with `validate-commit.sh` (`Closes:` parsing) and `update-board.ts`. The compound `EPIC-NNN-ISSUE-MMM` scheme was rejected because it parses as two tokens and blocks commits.
- **Metadata — blockquote, not YAML.** Issues use a blockquote header so `update-board.ts` (which parses blockquote) reads Status/Priority/SP/Epic/ID without modification; rich AI refs ride as extra blockquote lines. `update-board.ts` is never touched.
- **BOARD order.** `update-board.ts` sorts alphabetically (`id.localeCompare`), so `BOARD.md` is NOT in execution order. The SSOT of execution order is `EXECUTION-ORDER.md` + each epic's Issues table.
- **CP2 safety — durable + manifest-precise rollback.** Issues are written durably (like tk-design); Reject deletes exactly the manifest-recorded created-this-run paths (safe in `add` mode), never a glob or `git restore`.
- **Setup epic — no `vercel link` override.** `SK.md §7.1` stays absolute. `SETUP-020-cloud-bootstrap` is a manual runbook (Neon create / `vercel link` / `setup-e2e.ts`) + an automatable tail (migrate + verify). Resolves headless safety by construction.
- **CRUD is the unit.** A CRUD issue references multiple SCRs; `1 SCR = 1 issue` applies only to standalone non-CRUD screens.
- **ui-critic pre-assigned (not bolted on).** For `ui_touching` epics, the `ui-critic` issue is pre-assigned in Phase 3 so it passes through coverage/validation/sweep + lands in EXECUTION-ORDER; materialized as the epic's chain tail in Phase 4. `ui-critic` is NOT a Phase 7 validator (runs at `/implement` time on rendered UI).

### Deferred — Phase 2

- **`/implement-epic` workflow** — v1 emits topology + parallelism marks; consumer = `/implement` (one issue) for now. A future `/implement-epic` can fan out per chain head + parallelizable singleton.
- **Specialized `bkl-*` validators** with restricted tools — v1 uses 4 generic agents with scope injected via prompt. v2 if real-run pain.
- **`backlog-lint` script** — v1 verification leans on the Phase 7.6 sweep (runtime) + a fixture smoke. A `scripts/tools/backlog-lint.ts` (analogous to skill-lint) is v2 if the smoke proves insufficient.
- **Source-hash drift granularity** — v1 stores a content hash per consumed FT/SCR/ENT/AC in `COVERAGE-MATRIX.md`; finer-grained field-level drift is future.
